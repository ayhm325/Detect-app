# توثيق المشروع (العربي)

## مقدمة
هذا المستودع هو تطبيق ويب مبني باستخدام Next.js كمحرك الواجهة مع بنية حديثة للـ App Router، ويحتوي على أنظمة مصادقة، إدارة مرضى وأطباء، دردشة فورية عبر WebSocket، وطبقة وصول لقاعدة بيانات باستخدام Prisma.

الغرض من هذا المستند: إعطاء نظرة شاملة بالعربية توضح ما يُستخدم في المشروع ولماذا، وكيفية تشغيله وصيانته بسرعة.

## ملخص بنية المشروع
- `app/` : تطبيق Next.js الجديد (App Router). يحتوي على الصفحات، التخطيطات، ومحتوى متعدد اللغات (`[locale]`).
- `api/` : نقاط النهاية (API routes) على جانب الخادم للمصادقة، إدارة الأطباء، الدردشة، وما إلى ذلك.
- `components/` : مكونات React قابلة لإعادة الاستخدام (واجهات، نماذج، لوحات تحكّم).
- `lib/` : منطق مساعدة مثل واجهات Prisma، استعلامات، وعميل قاعدة البيانات.
- `scripts/` : أدوات نصية لمهام التطوير، استيراد/تصدير، إنشاء رسائل، وتجارب sockets.
- `prisma/` : ملف `schema.prisma` ومجلد الهجرات لإدارة قاعدة البيانات.
- `public/` : موارد ثابتة مثل أيقونات وملفات مرفوعة.
- `playwright-tests/` : اختبارات نهاية إلى نهاية باستخدام Playwright.

## التقنيات الرئيسية ولماذا تم اختيارها
- **Next.js (App Router)**: لتقديم صفحات SSR/SSG، إدارة المسارات، ودعم i18n. يسهل التعامل مع الأداء والـ SEO.
- **React**: لبناء واجهات تفاعلية ومكونات قابلة لإعادة الاستخدام.
- **Prisma**: ORM قوي لـ PostgreSQL مع هجرات تلقائية، نمذجة واضحة، وإنتاجية عالية للمطور.
- **WebSocket / socket-server**: لدعم المحادثات الفورية بين المرضى والأطباء — أسرع تجربة مستخدم في الوقت الحقيقي.
- **Playwright**: لإجراء اختبارات شاملة لـ end-to-end عبر سيناريوهات مستخدم حقيقية.
- **Tailwind / CSS Tokens**: لإدارة الأنماط بشكل سريع وقابل للتخصيص.

الاختيارات أعلاه تعطي توازنًا بين سرعة التطوير، الأداء، وقابلية الصيانة.

## ملفات وميزات مهمة ولماذا
- `next.config.mjs` / `next-intl.config.mjs` : إعدادات البناء والـ i18n — ضرورية لدعم لغات متعددة.
- `prisma/schema.prisma` : نموذج بيانات التطبيق (المستخدمين، الأطباء، الدردشات...) — مصدر الحقيقة لهيكل قاعدة البيانات.
- `lib/prismaClient.js` : نقطة إنشاء اتصال Prisma وإعادة استخدامه لتفادي اتصالات متعددة.
- `scripts/socket-server.js` و `start-socket-server.bat` : خادم السوكيت للمحادثات — منفصل عن واجهة Next.js لتبسيط إدارة الاتصالات.
- `app/[locale]/...` : صفحات مترجمة لكل لغة؛ تقسيم الإدخال وفقًا للـ locale يسهل توسيع الدعم اللغوي.
- `components/AuthGuard.js` و `api/auth/*` : حماية المسارات و endpoints — أساسي للأمان وتفويض الوصول.
- `playwright.config.js` و `playwright-tests/` : بنية لاختبارات التقبل، مهمة للحفاظ على استقرار التطبيق عبر التحديثات.

## الإعداد والتشغيل المحلي
1. تنصيب الحزم:

```bash
npm install
```

2. إعداد متغيرات البيئة: أنشئ ملف `.env` يحتوي على متغيرات مثل `DATABASE_URL`, `NEXT_PUBLIC_*` وبيانات المصادقة.

3. تشغيل هجرات Prisma (إن كانت موجودة):

```bash
npx prisma migrate deploy
# أو أثناء التطوير
npx prisma migrate dev
```

4. تشغيل الخادم في وضع التطوير:

```bash
npx next dev
```

5. تشغيل خادم السوكيت منفصلاً (إن لزم):

```bash
node scripts/socket-server.js
# أو تشغيل الملف باتش على ويندوز
start-socket-server.bat
```

6. بناء وإطلاق الإنتاج:

```bash
npx next build
npx next start
```

## السكربتات المهمة وصعوبتها/سبب وجودها
- `scripts/create-dev-token.mjs` و `scripts/create-test-doctor.js` : لتسهيل إعداد بيئة التطوير ببيانات تجريبية.
- `scripts/insert-message.mjs` و `scripts/list-chats.mjs` : أدوات إدارة دردشة للمطور أو للصيانة.
- `scripts/backfill-patients.js` و `fix-*` : إصلاحات بيانات أو عمليات ترحيل مؤقتة عندما تتغير النماذج.

هذه السكربتات تساعد على تقليل العمل اليدوي وإعادة استخدام إجراءات صيانة متكررة.

## أمان واعتبارات معمارية
- استخدم التحقق من الهوية (`api/auth`) وحماية الواجهات (`AuthGuard`) لمنع الوصول غير المصرح.
- تأكد من عدم تضمين مفاتيح أو سلاسل اتصال في المستودع — استخدم متغيرات بيئة آمنة.
- بالنسبة للهجرات الكبيرة: اتبع استراتيجيات zero-downtime (إضافة أعمدة قابلة للتجزئة، `NOT VALID` للتحقق لاحقًا).

## كيفية المساهمة
- اتباع نمط التفرع: `feature/xxx` وفتح Pull Request موجز يشرح التغييرات.
- كتابة اختبارات Playwright لأي تدفق مستخدم جديد أو تغييرات مهمة في الـ UI.
- تحديث `prisma/schema.prisma` مع هجرة منظمة عند تغيير نموذج البيانات.

## اختبارات
